Distributed Systems Microservices & EDA

Saga Orchestration Engine

High-concurrency distributed transaction manager orchestrating multi-database consistency across microservices without 2PC.

The Challenge

In modern decoupled architectures, traditional Two-Phase Commits (2PC) and monolithic shared databases cause catastrophic connection bottlenecks, cascading rollbacks, and distributed deadlocks. When scaling e-commerce transactions across independent database-per-service microservices, teams face dual-write anomalies (DB write succeeds but Kafka publish fails) and flash sale race conditions that lead to severe overselling.

Implementation Details

We built an Orchestration-based Saga System with strict database-per-service isolation (PostgreSQL, MongoDB, and Redis). The central Order Service acts as the Saga Orchestrator executing a Finite State Machine (FSM). To guarantee atomic state emission without distributed transactions, we implemented the Transactional Outbox Pattern: domain mutations and outgoing Kafka events are committed in the same local ACID transaction, with background workers streaming events to Kafka with zero dual-write vulnerabilities.

To eliminate overselling during high-concurrency flash sales, the Inventory Service enforces Pessimistic Row-Level Locking (`SELECT ... FOR UPDATE`), serializing concurrent reservations on contested SKUs while blocking race conditions in real time. For the Payment Service, atomic Redis `SETNX` distributed idempotency keys (24hr TTL) ensure duplicate webhooks or network retries never double-charge customers. If any downstream service fails (e.g., card declined or processor error), the orchestrator automatically triggers compensating transactions—restoring reserved stock in under 45ms with zero data leakage.
